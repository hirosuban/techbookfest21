## 1. 書籍概要

- **書籍名（仮）:** デミオを買ったので、カーライフをPythonで分析してみた
- **サブタイトル案:** 給油・走行・維持費を記録して、pandas・SQL・可視化で分析する
- **ターゲット層:**
  - Pythonを使い始めたエンジニア
  - pandasを勉強しているが、題材がなくて手が止まる人
  - SQLやデータ分析を実データで練習したい人
  - 自分の生活データを分析してみたい人
  - 車を持っていて、燃費・維持費などを数字で見てみたい人
- **ゴール:**
  - 2026年7月に購入した中古マツダ デミオの給油・走行・維持費データを、pandas・SQL（SQLite /
    DuckDB）・matplotlibで記録〜分析〜可視化するところまでを一冊にまとめる
  - 11月末の技術書典での頒布（デジタル版 / 必要に応じて物理本）

### この本でやること

2026年7月に中古のマツダ デミオを購入したが、購入直後からデータを収集していたわけではない。
しばらく普通に車に乗った後、「せっかく車を買ったんだから、カーライフをデータにしてPythonで
分析してみたら面白いのでは」と思い、給油・走行距離・維持費などの記録を始めた。ところが過去の
ログには欠損がある（7月の給油記録が残っていない、ODOが分からない、レシートがない、記録方法が
途中で変わっている等）。つまり最初から綺麗なデータセットが存在するわけではない。

そこで本書では「自分の生活からデータを作り、欠損や不完全さを抱えたまま分析する」という流れ
そのものを題材にする。

### コンセプト：「自動車データ分析」の本ではない

既存の自動車データセットを使って CSV→pandas→グラフ→分析結果、というだけの本にはしない。
本書の主題は、

```text
生活 → データを記録する → データを設計する → 欠損・ミスと向き合う
     → Pythonで加工する → SQLで分析する → 可視化する → 自分の生活について考える
```

という一連のプロセス。デミオは「分析対象」であると同時に、データ分析を始めるきっかけになる。

### データを捏造しない（重要なルール）

本書では、実際には存在しない過去のデータを「それっぽく復元」しない（例：「7月の燃費は
13.8km/Lだったはず」のような推測を実測値として扱わない）。必要であれば、**実測値 / 推定値 /
人工データ**を明確に区別して扱う。

> 旧企画（黄金比パート）で「検出の不具合だと思っていた乖離が、実は実車の実寸プロポーション
> どおりだった」という訂正を経験した反省も踏まえ、推測と実測を混同しない姿勢は本書でも引き継ぐ。

## 2. データ設計

本書では、データを以下の3種類に分ける。

```text
data/
├── real/       my_demio.csv             … 実際の自分のデミオから収集したデータ（本書の中心）
├── sample/     sample_fuel_log.csv ...  … 読者が同じコードを実行できるサンプルデータ
└── synthetic/  simulated_1year.csv      … 実データだけでは足りない場合に生成する人工データ
```

### 給油データ（最低限）

| カラム | 内容 |
|---|---|
| date | 給油日 |
| odo | 給油時のODO |
| liters | 給油量 |
| amount | 支払金額 |

必要に応じて `unit_price`（1Lあたり単価）、`station`（ガソリンスタンド）、`memo` を追加する。

### 維持費データ

ガソリン・駐車場・自動車保険・税金・車検・メンテナンス・洗車・その他を記録し、月あたり維持費・
年間維持費・1kmあたりコストなどを計算する。

## 3. 「1年分のデータがない」問題

執筆開始時点（2026年7月購入）では1年分の実データは存在しないため、「1年間のカーライフを
分析しました」という構成にはしない。代わりに、**実データ（2026年7月〜11月ごろの実際のデミオの
データ）／サンプルデータ（読者が試す用）／人工データ（1年間の傾向を見るための生成データ）**を
明確に分離する。

## 4. 本の目次案（予定）

1. **第1章：デミオを買ったのでデータを取り始めた**
   なぜ車をデータ化するのか／2026年7月のデミオ購入／しかし購入時点ではログを取っていなかった
   ／過去データが足りない／それでも分析してみる
2. **第2章：カーライフのデータを設計する**
   何を記録するか／給油データ／ODO／維持費／データの粒度／CSVの設計／欠損値をどう扱うか
3. **第3章：給油データをPythonで読み込む**
   Python環境／pandas／CSV／DataFrame／型／日付／欠損値
4. **第4章：デミオの燃費を計算する**
   ODOから走行距離を求める（`diff()`）／給油量から燃費を求める／欠損値・異常値／燃費の集計
5. **第5章：カーライフの支出を分析する**
   ガソリン代／駐車場／保険／税金／メンテナンス／月別集計／年間コスト
6. **第6章：SQLでカーライフを分析する**
   SQLite / DuckDB／テーブル設計／SELECT・WHERE・GROUP BY・JOIN／月別集計／1kmあたりコスト
7. **第7章：グラフにしてみる**
   matplotlib／時系列データ／燃費推移／ガソリン価格／支出推移／グラフから何が分かるか
8. **第8章：データが足りないなら作ってみる**
   なぜ人工データが必要なのか／実データと人工データを分ける／1年間のカーライフをシミュレーション
   ／季節による燃費変化／ガソリン価格の変化／長期間の可視化
9. **第9章：自分のカーライフを分析する**
   実際に収集したデミオのデータを使い、何km走ったか／どれくらい給油したか／いくら使ったか／
   燃費はどうだったか／1kmあたりいくらかかったかを見て、「車を持つと実際どれくらいお金が
   かかるのか」を自分のデータから考える
10. **第10章：これから1年間データを集める**
    本を書いて終わりではなく、2026年7月→11月→2027年…とデータが蓄積されていく継続的な
    収集につなげる。将来的にはGPS・OBD-II・走行ルート・運転時間・気温・天気・メンテナンス履歴
    なども分析対象にできる（OBD2でのデータ取得の準備メモは[docs/obd2_csv.md](obd2_csv.md)。
    iPhone + Veepeak OBDCheck BLE + Car Scanner ELM OBD2アプリで車速・RPM・水温等をCSV出力する
    構想。2026-10-04時点ではアダプター到着待ちで、実データはまだ無い）
11. **おわりに**

> 章数・ページ配分は未確定。11月末までの残り約8週間で10章＋おわりはボリュームが大きいため、
> 執筆を進めながら統合・簡略化を検討する（次回やること参照）。

## 6. 既存サービスとの差別化

給油記録・燃費管理・維持費管理・メンテナンス管理・グラフ表示を提供する既存アプリは既にある。
本書は「カーライフ管理アプリを作る」ことを主目的にしない。既存サービスを使ってもよく、重要なのは
「自分の生活データを、自分で扱えるようになる」こと（カーライフ管理アプリ→CSV→Python→pandas→
SQL→自分だけの分析、という使い方もできる）。

## 7. 技術書典でのゴール

完成された「1年間のカーライフ分析」を見せることが目的ではない。「車を買った。でもデータがない。
じゃあ自分で集めてみよう」から始まり、記録→データ設計→Pythonで加工→SQLで分析→グラフ化→
自分の生活について考える、という過程を読者に体験してもらう。本そのものを「カーライフデータ分析
プロジェクトの最初の4か月」として扱い、2027年以降もデータを蓄積し続ける前提。
