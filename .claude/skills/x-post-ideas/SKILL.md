# X投稿案を考える

ユーザーが担当するデミオのパート（「デミオを買ったので、カーライフをPythonで分析してみた」）の宣伝用に、
X投稿の下書きを作る。投稿の題材はデミオのパートだけで、他の著者のパートは扱わない。
**投稿はしない。** 下書きをチャットで提示する。ユーザーが選んでGoogleスプレッドシートの「投稿」シートに貼り、
「投稿OK」にすると自動で投稿される（仕組みは [promo/x_autopost/README.md](../../../promo/x_autopost/README.md)）。

- 投稿するアカウント：[@hirosuban](https://x.com/hirosuban)（デミオのパートを書いている著者本人のアカウント。本人の一人称で書く）
- 同じアカウントから他の2人のパートの投稿も出るので、本文の先頭に必ず`【デミオ編】`を付ける。
  付いていないと自動投稿のチェックで弾かれる。
- 本はサークル **SYK出版** の合同誌で、デミオはその1パート。販売の告知（いつ・どこで買えるか）を入れるときは、
  単著に見えないよう「SYK出版の合同誌に書いています」のように添える。合同誌のタイトル・公式ハッシュタグは
  [docs/tech_book_plan.md](../../../docs/tech_book_plan.md) の「1. 書籍概要」冒頭に記録してある。
  そこに書かれていなければ `[合同誌タイトル]` のようなプレースホルダにしてユーザーに聞き、教わったら同じ箇所に追記する。

## 1. 読むもの

1. [docs/ref_todokeru_kufuu.md](../../../docs/ref_todokeru_kufuu.md)：「届ける工夫」の要約。投稿の判断基準はここに従う。
2. [docs/tech_book_plan.md](../../../docs/tech_book_plan.md)：書名・ターゲット・コンセプト・開催日・スケジュール。
3. `logs/` の直近のログ（新しい順に3〜5日分程度）と `git log --oneline -20`：投稿ネタの素材。
4. ユーザーが「この話で」と題材を指定したら、それを優先する。

## 2. いまの時期を判定する

今日の日付と計画書にある開催日から、時期を決める。開催日・会期・入稿〆切が計画書で確定していなければ、
**推測で書かず** `[開催日]` のようなプレースホルダにして、確定しているかユーザーに聞く。

| 時期 | 投稿の中心（要約の章） |
|---|---|
| 執筆中（〜入稿） | 執筆の途中経過・裏話・決まっていないことも出す（2章）。情報を出さない期間を1週間以上作らない |
| 入稿〜開催直前 | 表紙・目次・お品書き・試し読み・書籍ページの公開。日付は「今週日曜（11/xx）」形式（3章・4章） |
| 開催当日 | 時刻・場所・入場方法・オンラインでも買えること。設営完了などの写真付き（3.3〜3.5） |
| 開催後 | 会期中はオンラインで買えること、会期後にどこで買えるか、感想へのお礼・紹介（3.6・3.14・6章） |

固定ポストを替えるべき時期（3.9）なら、固定ポスト用の案も1本入れる。

## 3. 下書きを作る

3〜5本の案を、題材や切り口が重ならないように作る。各案は次の点を守る。

- **何の話か分かるようにする**（3.5）：その1本だけ読んでも、技術書典で出る本の話だと分かるようにする。
  告知系の投稿には、いつ・どこで買えるか（または、いつから分かるか）を入れる。
- **ハッシュタグ**：`#技術書典`（ナンバリングなしの公式推奨）と、合同誌の公式ハッシュタグ`#SYK出版`の2つを付ける。
  どちらかが欠けると自動投稿のチェックで弾かれる。
- **日付**：具体的に書く。直前なら「今週日曜（11/xx）」のように距離感も分かる書き方にする（3.3）。
- **卑下しない**（3.2）：「大した内容じゃないけど」などは書かない。面白いところを素直に書く。
- **コピペ禁止**（3.10）：過去の案の言い回しを使い回さず、毎回新しい情報を1つ入れる。
- **間口を広く**（2.4・2.5）：車好きだけでなく「pandasの題材がなくて手が止まる人」にも刺さる言い方を混ぜる。
  元ペーパードライバーだったという経緯は、本の売り込みに使ってほしいとユーザーから言われている。
- **データを捏造しない**：燃費・距離・回数などの数値は `logs/` と `output/` にある実測値だけを使う。
  推定値なら推定と書く。ログにない数字を作らない。
- **個人情報を出さない**：自宅や駐車場の場所、ナンバー、詳細なルートやGPS座標など、生活圏が特定できる情報は入れない。
  `data/real/` は非公開データなので、そこから生の値を貼らない。
- **長さ**：Xの上限は加重280（日本語は1文字2、URLは23）、つまり日本語なら全角140字程度。
  自動投稿はスレッドに対応していないので、1投稿に収める。リンクを入れると投稿料が約$0.015から約$0.20に上がる。
  文字数は次で確認できる（自動投稿の`xlen`と同じ数え方）。

  ```bash
  python3 -c "import sys,re,unicodedata as u;R=[(0,0x10FF),(0x2000,0x200D),(0x2010,0x201F),(0x2032,0x2037)];t=re.sub(r'https?://\S+','x'*23,u.normalize('NFC',sys.stdin.read().strip()));print(sum(1 if any(a<=ord(c)<=b for a,b in R) else 2 for c in t),'/ 280')" <<'EOF'
  ここに本文
  EOF
  ```

## 4. 出力の形

案ごとに次をまとめて、チャットで提示する。

```markdown
### 案1：<一言で題材>
<投稿本文>

- 文字数：<加重>/280
- 添付画像：<付ける画像の提案。output/ 内の既存グラフならパス、なければ「校正中の原稿の写真」など撮れるもの>（3.4）
- 狙い：<要約のどの工夫に沿っているか（例：2.2 裏話で認知を得る）>
- 素材：<元にしたログのパス>
- シートに貼る値：パート＝`デミオ編`／画像＝<上の画像をドライブの共有フォルダ「SYK出版 宣伝」に置いてリンクを貼る>
```

最後に、次に投稿しておくとよい時期・題材を1〜2行で添える（例：「表紙が決まったら初公開ポスト」）。
ユーザーが保存を頼んだときだけファイルに書き出す。
